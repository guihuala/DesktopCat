# 《假装有猫》原型开发计划

## 一、原型目标

首个原型用于验证以下核心体验：

1. 监控视角下的猫在没有玩家操作时，是否仍然显得“像活的”。
2. 点击、喂食、呼唤等轻量交互，是否能提供清晰且可爱的情绪反馈。
3. 在线挂机获得家具、再将家具摆入房间，是否能形成持续打开游戏的动力。

游戏定位为“3D 桌面宠物 / 轻挂机 / 情绪陪伴”。原型阶段不追求完整内容量，而应优先证明陪伴感、低打扰交互和家具收集闭环成立。

### 策划口径

总 GDD 仍描述为“挂机获得小鱼干，再购买家具”，较新的《挂机刷家具系统》已调整为“每 30 分钟直接获得家具，不计算离线收益”。

原型以较新的直接掉落家具方案为准，减少货币和商店开发，更快验证核心收集循环。

## 二、原型范围

### 必须完成

- Windows 透明、无边框、置顶桌宠窗口。
- 监控画面式固定比例窗口。
- 一只可运行的 3D 猫和一个小型房间。
- 猫咪自主状态：游荡、打盹、睡眠、进食、靠近镜头、离开画面。
- 精力与饥饿两个基础属性。
- 点击猫、喂食、呼唤三种玩家互动。
- 玩家鼠标活跃度影响“靠近镜头”的触发概率。
- R 键呼出手机式操作托盘。
- 昼夜模式：跟随系统、白天、夜晚。
- 在线计时并生成家具。
- 家具领取、库存、图鉴和房间锚点摆放。
- 设置：置顶、点击穿透、桌宠/UI 缩放、音量、帧率。
- 基础存档。

### 简化实现

- 猫外观只做 2 种毛色和 2 种体型，用于验证配置与换装管线。
- 房间只做猫窝、食盆、地毯、桌面、玩具 5 类锚点。
- 家具准备约 12 件：8 件常规、3 件稀有、1 件珍藏。
- 原型测试时将掉落周期从 30 分钟缩短到 1～3 分钟，并提供调试按钮。
- “呼唤”先使用默认音效，不实现录音。
- 合成只做内部数值模拟或静态界面，不接入正式流程。
- 昼夜只改变灯光和环境，不影响猫的行为。

### 暂缓内容

- 完整七种毛色、尾巴、腿长和异瞳组合。
- 排泄及猫砂盆完整演出。
- 录音、麦克风监听和系统权限流程。
- 家具九合一、配方合成和随机合成。
- 小鱼干货币与商店。
- 多显示器切换、快捷键重绑定。
- 完整多语言和高级画质设置。
- 珍藏标签、隐藏家具和长期图鉴解锁。

## 三、技术方案

继续使用当前 Unity 2022.3、URP 和已有工程，不推倒重写。

### 可保留的现有基础

- `WindowController`：透明、置顶、无边框、穿透、拖拽与吸附。
- `UIManager`、`UIPanel`、`SettingsPanel`：桌宠 UI 面板框架。
- `GameEventBus`：模块间消息传递。
- `SaveManager`：存档入口。
- `CatBodyController`：BlendShape 验证基础。

### 建议新增模块

- `PetStateController`：精力、饥饿和当前状态。
- `PetBehaviorBrain`：有限状态机与行为权重。
- `PetMovementController`：房间内移动和目标点选择。
- `PetInteractionController`：点击、喂食、呼唤。
- `PlayerActivityTracker`：鼠标活跃度和闲置时长。
- `PetPresentationController`：动画、表情、音效和气泡反馈。
- `DayNightController`：读取系统时间并控制环境。
- `OnlineRewardService`：在线累计、待领取数量与家具抽取。
- `FurnitureInventory`：持有、摆放、锁定和图鉴记录。
- `FurniturePlacementController`：锚点摆放及替换。
- `PrototypeDebugPanel`：调整数值、强制行为、加速时间和生成家具。

猫咪行为采用“有限状态机 + 权重评分”。原型阶段不引入复杂行为树。排泄等强制行为后续可以作为高优先级状态加入。

### 数据配置

使用 ScriptableObject 管理原型配置：

- `PetTuningConfig`
- `BehaviorDefinition`
- `FurnitureDefinition`
- `FurnitureDropTable`
- `InteractionDefinition`

运行状态与配置分离，确保策划可以调整阈值、权重、持续时间和掉落概率。

## 四、四周开发排期

以下排期假设配置为 1 名程序、1 名美术兼动画、策划兼职验收。

### 第 1 周：桌宠可运行

目标：得到可以长期放在桌面上的猫。

- 整理现有窗口、UI、事件和存档模块。
- 完成监控房间场景与摄像机。
- 接入猫模型、Animator 和基础移动。
- 实现游荡、打盹、睡眠三个状态。
- 建立精力、饥饿配置。
- 增加行为调试面板。
- 输出第一个 Windows 可执行版本。

验收标准：桌宠可置顶、拖拽和穿透；猫能在房间中自主活动至少 30 分钟，不报错或卡死。

### 第 2 周：陪伴与互动

目标：验证猫是否具有“活物感”。

- 加入进食、靠近镜头、离开画面。
- 实现点击猫、喂食和默认音效呼唤。
- 接入鼠标活跃度。
- 完成动画、BlendShape、音效和气泡反馈层。
- 实现 R 键手机托盘。
- 实现系统昼夜和手动切换。

验收标准：每种互动都有即时反馈；睡眠等不可打断状态符合规则；连续观察 20 分钟能看到不少于 4 种自主行为。

### 第 3 周：家具收集闭环

目标：完成“挂机—领取—摆放—继续收集”。

- 实现在线累计计时与最多 6 件待领取。
- 实现 88% / 10% / 2% 档位抽取。
- 实现家具库存、重复持有和永久图鉴。
- 实现 5 类家具锚点和摆放替换。
- 制作约 12 件原型家具。
- 保存在线进度、库存、图鉴和摆放状态。
- 增加加速时间与批量模拟工具。

验收标准：退出重开后数据一致；家具可领取、重复持有、摆放和替换；可模拟至少 1000 次掉落并检查概率与异常。

### 第 4 周：整合与试玩

目标：形成可交付的体验原型。

- 完成设置面板中的必要选项。
- 完成首次启动猫外观选择。
- 调整行为频率，避免猫过于吵闹或长期无动作。
- 调整窗口遮挡、UI 尺寸和操作路径。
- 进行 2～3 轮内部试玩。
- 修复高频错误并制作演示版本。
- 记录合成、商店和完整外观系统的后续技术接口。

验收标准：新玩家在没有说明的情况下，5 分钟内能完成呼出菜单、喂猫、领取家具并摆放家具；程序可稳定运行 2 小时。

## 五、体验验收指标

原型重点观察：

- 玩家是否会在工作过程中主动看猫。
- 猫咪行为是否自然，是否重复得过于明显。
- 互动反馈是否值得玩家再次触发。
- UI 是否打扰桌面工作。
- 家具领取是否能让玩家产生期待。
- 玩家是否理解家具可以摆放和重复获得。
- 30 分钟正式掉落间隔是否过长。
- “直接掉家具”是否比“小鱼干—商店”更符合轻量体验。

建议邀请至少 5 名目标玩家，各运行 1～2 小时，并记录：

- 主动查看次数。
- 主动互动次数。
- 手机托盘误操作次数。
- 家具领取与摆放完成率。
- 对猫咪“像不像活的”的主观评分。
- 希望长期保留的功能和最打扰的功能。

## 六、主要风险

- 当前工程使用 Unity 2022.3，但 URP 包版本为 17.0.3，需要尽早验证编辑器、材质和构建兼容性。
- Windows 原生透明与穿透功能只能在真实构建中完整验证，不能只依赖编辑器。
- “真实监控窗口”与传统透明桌宠的视觉方向需要尽早统一。
- 猫咪行为策划中的阈值仍为临时值，必须全部配置化。
- 家具池扩张后会稀释新家具掉率；原型阶段先验证重复体验，不提前设计完整长期经济。
- 动画数量不足会直接影响“猫是否像活的”，应优先保证状态过渡和少量高质量动作，而不是堆叠系统。
