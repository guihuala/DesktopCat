# 《假装有猫》原型详细开发目标

## 1. 使用方式

本文档将原型计划拆分为可执行任务。每项任务均包含优先级、依赖和完成定义，可直接录入任务管理工具。

优先级说明：

- `P0`：原型闭环必需；未完成时不能进入体验验收。
- `P1`：明显提升体验或测试效率；尽量在原型期完成。
- `P2`：可延期优化；不阻塞原型结论。

任务状态建议使用：`待处理`、`进行中`、`待验收`、`已完成`、`已阻塞`。

## 2. 原型总完成定义

满足以下条件时，原型才算完成：

- Windows 构建可稳定运行 2 小时，无阻断性报错、窗口失控或存档损坏。
- 猫能在没有玩家输入时自主完成至少 4 种可辨识行为。
- 玩家可以点击猫、喂食、呼唤，并获得动画、表情或音效反馈。
- 玩家可以完成“在线等待—领取家具—查看库存—摆放家具”的完整流程。
- 退出并重新启动后，猫外观、设置、家具库存、图鉴和摆放状态均正确恢复。
- 新玩家无需说明，可在 5 分钟内找到手机托盘、完成一次互动并摆放一件家具。
- 所有临时数值均来自配置，不硬编码在行为脚本中。

## 3. 里程碑总览

| 里程碑 | 目标 | 计划完成时间 | 退出条件 |
|---|---|---:|---|
| M0 工程基线 | 建立稳定、可调试、可构建的开发基础 | 第 2 天 | 可生成 Windows 开发包，核心服务启动正常 |
| M1 猫活起来 | 猫能自主移动、休息和切换状态 | 第 1 周末 | 连续运行 30 分钟，无卡死且出现 3 种基础行为 |
| M2 猫有回应 | 玩家能轻量互动，猫有明确反馈 | 第 2 周末 | 三种互动可用，连续观察出现至少 4 种行为 |
| M2.5 配置架构升级 | 为更多属性和复杂行为建立可扩展配置 | M2 验收后 | 新属性和新行为可独立配置，不继续膨胀单一配置类 |
| M3 收集闭环 | 家具可获得、保存、查看和摆放 | 第 3 周末 | 完整闭环可重复执行，重启后数据一致 |
| M4 可试玩版本 | 设置、引导、调优和稳定性达标 | 第 4 周末 | 通过内部验收并输出可分发构建 |

## 4. M0：工程基线

### M0-01 确认运行环境与构建基线（P0）

目标：确保当前 Unity、URP、目标平台和项目依赖可以稳定协作。

任务：

- 确认 Unity 版本为 `2022.3.62f3c1`。
- 验证 URP 17.0.3 在当前编辑器中无包解析错误、材质大面积丢失或构建失败。
- 确认 Windows x86_64 为原型目标平台。
- 建立 Development Build 构建配置。
- 记录编辑器启动、场景运行和 Windows 构建的已知警告。

完成定义：

- 项目可无编译错误进入 `GamePlay` 场景。
- 可以生成并启动 Windows 开发构建。
- 严重兼容问题已有明确处理结论，不留未知阻塞项。

### M0-02 整理模块目录与命名空间（P1）

目标：为后续模块提供稳定位置，不大规模移动现有资产。

建议目录：

```text
Assets/Scripts/DesktopPet/
  Window/
  UI/
  Input/
  Pet/
    State/
    Behavior/
    Movement/
    Presentation/
  Item/
  Furniture/
  Config/
  Save/
  Debug/
```

完成定义：

- 新代码按模块存放。
- 新增运行时代码统一使用 `DesktopPet` 子命名空间。
- 不破坏现有场景和 Prefab 引用。

### M0-03 建立运行时上下文（P0）

目标：为猫、窗口、存档和 UI 提供明确的初始化顺序。

任务：

- 创建原型启动入口或场景级 Bootstrap。
- 注册窗口、配置、存档、猫状态、家具库存等服务。
- 定义新游戏与读取存档两条启动路径。
- 明确暂停、退出和应用失焦时的处理规则。

完成定义：

- 所有核心模块只初始化一次。
- 场景重载不会出现重复事件订阅或重复计时。
- 初始化失败时输出可定位的错误信息。

### M0-04 扩展调试工具（P0）

目标：让行为、时间和掉落无需等待即可验证。

功能：

- 查看并修改饥饿、精力。
- 强制切换猫咪行为。
- 调整时间倍率。
- 增加在线累计时间。
- 生成指定档位或指定家具。
- 清空或重载原型存档。
- 显示当前状态、目标点、行为评分和不可打断原因。

完成定义：

- 所有 P0 系统均可通过调试面板快速进入目标状态。
- 调试功能只在编辑器或 Development Build 中出现。

## 5. M1：猫活起来（已于 2026-09-03 验收）

### M1-01 创建猫咪数值模型（P0）

依赖：M0-03。

数据：

- 精力 `Energy`，范围 0～100。
- 饥饿 `Hunger`，范围 0～100，数值越高表示越饿。
- 当前行为、行为开始时间和不可打断标志。

任务：

- 创建 `PetStateController`。
- 创建 `PetTuningConfig`。
- 实现数值边界限制与变化事件。
- 为调试面板提供只读快照和受控修改接口。

完成定义：

- 数值不会超出范围。
- 数值变化可被 UI、行为和存档模块监听。
- 所有变化速度和阈值均可配置。

### M1-02 建立行为框架（P0）

依赖：M1-01。

目标：使用有限状态机加权重评分选择行为。

行为接口至少包含：

- 是否允许进入。
- 当前评分。
- 进入、更新和退出。
- 是否可被打断。
- 最短持续时间和冷却时间。

完成定义：

- 同一时间只有一个主行为运行。
- 切换行为时必定调用旧行为退出和新行为进入。
- 睡眠等不可打断行为不会被普通随机行为打断。
- 没有合法候选时安全回退到待机。

### M1-03 实现房间移动（P0）

依赖：M1-02。

任务：

- 定义可行走区域和行为目标点。
- 实现猫转向、移动、到达和失败处理。
- 提供普通走、快走或跑的速度配置。
- 防止猫穿出房间、长期卡在障碍或无限寻路。

完成定义：

- 猫可到达至少 5 个测试目标点。
- 目标不可达时能在超时后取消并重新选择。
- 移动与待机动画切换无明显抖动。

### M1-04 实现游荡（P0）

依赖：M1-03。

规则：

- 精力足够且当前可进入主动行为时参与评分。
- 随机选择可行走目标点。
- 游荡期间缓慢消耗精力。
- 到达后停留短暂随机时长，再退出或选择新目标。

完成定义：

- 连续运行 10 分钟能多次选择不同目标。
- 不会在两个相邻点间高频抖动。

### M1-05 实现打盹（P0）

依赖：M1-02。

规则：

- 精力处于低值区间，且距离猫窝较远时提高评分。
- 原地进入母鸡蹲或临时休息表现。
- 缓慢恢复精力。
- 达到退出阈值后结束。

完成定义：

- 状态进入和退出阈值不同，避免边界反复切换。
- 打盹期间不会继续移动。

### M1-06 实现睡眠（P0）

依赖：M1-03。

规则：

- 精力极低或接近猫窝时优先进入。
- 先移动到猫窝，再进入睡眠循环。
- 睡眠期间较快恢复精力且默认不可被普通行为打断。
- 达到退出阈值后播放起身并恢复主动状态。

完成定义：

- 到达猫窝失败时有原地睡眠或打盹降级路径。
- 睡眠过程不被游荡或靠近镜头打断。

### M1-07 建立基础动画适配层（P0）

依赖：M1-04、M1-05、M1-06。

任务：

- 创建 `PetPresentationController` 或 `PetAnimationController`。
- 将玩法意图映射到待机、行走、打盹、睡眠、起身动画。
- 动画参数名集中配置或封装，不散落在行为代码中。
- 对缺失动画提供安全回退。

完成定义：

- 替换 Animator Controller 时无需修改行为逻辑。
- 动画缺失不会导致行为流程无法退出。

### M1 里程碑验收

- 使用正式速度连续运行 30 分钟。
- 至少出现游荡、打盹、睡眠三种行为。
- 无状态卡死、数值越界、重复初始化和持续刷错。
- 可以从调试面板查看每次行为选择原因。

## 6. M2：猫有回应（已于 2026-09-03 验收）

### M2-01 实现猫咪点击交互（P0）

依赖：M1-07。

任务：

- 为猫建立可靠的点击碰撞区域。
- 区分点击 UI、拖动窗口和点击猫。
- 点击后触发表情、动画、音效或气泡中的至少两项。
- 增加短冷却，避免连续点击造成动画失控。

完成定义：

- 点击 UI 不会误触猫。
- 点击猫不会意外拖动窗口。
- 快速连续点击不会产生事件堆积。

### M2-02 实现喂食与进食行为（P0）

依赖：M1-03、M2-01。

流程：

1. 玩家从手机托盘选择喂食。
2. 食盆进入可用状态。
3. 猫在允许被打断时提高进食评分。
4. 猫移动至食盆并播放进食表现。
5. 饥饿值逐步下降，到达阈值后退出。

完成定义：

- 睡眠等不可打断状态下，喂食请求可排队或明确拒绝，不丢失且不强切状态。
- 食盆目标不可达时有超时反馈。
- 饥饿值变化与表现同步。

### M2-03 实现呼唤（P0）

依赖：M2-01。

任务：

- 播放默认呼唤音效。
- 根据猫当前状态和配置概率决定回应。
- 回应时看向镜头或触发靠近镜头行为。
- 睡眠期间降低回应概率；不可打断行为不响应。

完成定义：

- 调试面板可强制回应或不回应。
- 玩家能理解猫是否听见、为何没有靠近。

### M2-04 跟踪玩家鼠标活跃度（P0）

任务：

- 统计最近一段时间的鼠标移动和点击频率。
- 输出活跃、普通、闲置三档状态。
- 只保留即时统计，不记录具体输入内容。
- 应用失焦时不把异常输入计入活跃度。

完成定义：

- 活跃状态变化可通过事件读取。
- 高频鼠标活动能稳定提高靠近镜头评分，但不保证立即触发。

### M2-05 实现靠近镜头（P0）

依赖：M1-03、M2-04。

任务：

- 设置镜头附近目标点。
- 根据随机因素、呼唤和鼠标活跃度计算评分。
- 到达后播放看镜头或大头特写表现。
- 设置冷却，避免频繁挡住监控画面。

完成定义：

- 正常情况下不会连续两次高频触发。
- 睡眠和进食期间不能被该行为打断。

### M2-06 实现离开画面（P1）

依赖：M1-02。

规则：

- 仅在可进入主动行为时随机触发。
- 离开后隐藏或移动到画面外 30～120 秒。
- 期间行为锁定，但数值仍按规则更新。
- 回归时进入待机或恢复状态。

完成定义：

- 玩家能分辨“猫暂时离开”而不是程序故障。
- 重载存档时不会让猫永久消失。

### M2-07 实现手机托盘（P0）

依赖：现有 `UIManager`、`UIPanel`。

功能：

- R 键打开或关闭。
- 可拖拽，不与窗口拖动冲突。
- 提供喂食、呼唤、家具、设置四个入口。
- 打开时临时关闭点击穿透，关闭后恢复原设置。

完成定义：

- Esc 能关闭最上层面板。
- 多次开关不会破坏穿透状态。
- 托盘不遮挡猫主体的主要观察区域。

### M2-08 实现昼夜表现（P1）

任务：

- 提供跟随系统、固定白天、固定夜晚三种模式。
- 跟随系统时读取本地时间。
- 切换环境灯光、背景和后处理配置。
- 将选择写入存档。

完成定义：

- 模式切换即时生效。
- 昼夜只影响表现，不改变原型行为权重。

### M2 里程碑验收

- 点击、喂食、呼唤均可完成并有明确反馈。
- 连续观察 20 分钟能看到至少 4 种自主行为。
- 手机托盘、窗口拖动、猫点击和穿透状态互不冲突。
- 玩家高频移动鼠标时，靠近镜头的触发率有可观察提升。

## 6.5 M2.5：配置架构升级

目标：在增加心情、清洁、亲密度等新属性或大量新行为之前，将当前集中式 `PetTuningConfig` 拆分为职责清晰、可独立维护的配置，避免每次扩展都同时修改状态、行为、存档和调试界面。

### 启动条件

满足以下任意一项时启动本任务：

- 准备增加第 3 个可变化的猫咪基础属性。
- 准备一次新增 3 种或以上行为。
- 需要支持不同猫咪性格、成长阶段或难度使用不同参数。
- 策划需要在不修改代码的情况下组合行为进入和退出条件。

在上述条件出现前，继续使用当前 `PetTuningConfig`，不提前建设完整通用框架。

### M2.5-01 拆分配置职责（P1）

任务：

- 保留一个原型总配置作为配置集合入口。
- 将基础属性、移动、互动和行为参数拆分为独立配置。
- 每种行为使用独立的 `BehaviorDefinition`，保存持续时间、冷却、优先级、是否可打断等公共参数。
- 将行为专属参数放在对应行为配置中，不继续添加到单一大类。

完成定义：

- Inspector 中可以按模块快速找到参数。
- 修改一种行为的配置不会影响无关行为配置。
- 旧 `PetTuningConfig` 数据有明确迁移方式，现有 M1/M2 表现不发生意外变化。

### M2.5-02 建立可扩展属性模型（P1）

任务：

- 为属性定义稳定 ID、显示名称、初始值、上下限和自然变化速度。
- 运行时统一处理边界限制、变化事件和只读快照。
- 调试面板根据属性定义自动生成显示和调节控件。
- 存档按属性 ID 保存，并为新增、删除和改名提供版本迁移入口。

完成定义：

- 新增一个普通数值属性时，无需修改状态控制器和调试面板主体代码。
- 缺失、重复或未知属性 ID 会给出明确校验信息。
- 旧存档缺少新增属性时能够使用默认值正常启动。

### M2.5-03 配置化行为条件（P1）

任务：

- 支持以配置表达常用条件：属性范围、当前行为、外部请求、冷却和随机权重。
- 支持配置行为进入条件、退出条件和评分修正。
- 复杂流程仍允许使用专用代码实现，不强制所有逻辑完全数据化。
- 在编辑器或开发包中显示行为被阻止的可读原因。

完成定义：

- 常见阈值调整无需修改行为代码。
- 多个条件可以组合，并有确定、可测试的计算顺序。
- 配置非法或引用缺失时安全回退到待机，不导致猫咪卡死。

### M2.5 里程碑验收

- 使用迁移后的配置重复执行 M1、M2 验收，结果与改造前一致。
- 新增一个测试属性和一个测试行为，验证扩展过程不需要修改核心状态控制器。
- 存档升级、配置校验和调试界面均能识别新增属性。
- 删除测试内容后不残留无效 ID 或存档错误。

## 7. M3：家具收集闭环（已于 2026-09-03 验收）

### M3-01 建立家具配置（P0，待美术资源后验收）

数据至少包含：

- 家具 ID 和显示名称。
- Prefab 或资源引用。
- 档位：常规、稀有、珍藏。
- 基础标签。
- 锚点类型。
- 图鉴描述和图标。

完成定义：

- ID 唯一且启动时自动校验。
- 缺失资源或非法档位会输出明确错误。
- 原型至少配置 12 件家具。

### M3-02 实现在线累计（P0，待验收）

规则：

- 只累计程序运行期间的在线时间。
- 正式周期为每 30 分钟产生 1 个领取单位。
- 最多累计 6 个单位。
- 未满一个周期的进度在退出时保存。
- 不计算退出期间的离线收益。
- 应用失焦或最小化期间仍累计，只要程序进程保持运行。

完成定义：

- 修改系统时间不能直接获得大量奖励。
- 暂停、失焦和最小化策略已有明确实现。
- 调试时间倍率不污染正式配置。

### M3-03 实现家具抽取（P0，待验收）

规则：

1. 先按常规 88%、稀有 10%、珍藏 2% 判定档位。
2. 再从对应档位的已解锁家具中等概率抽取。
3. 每个领取单位必定获得一件家具。

完成定义：

- 某档位池为空时有明确降级策略，不返回空奖励。
- 可固定随机种子复现测试结果。
- 批量模拟 1000 次时，结果分布无明显实现偏差。

### M3-04 实现库存与图鉴（P0，待验收）

任务：

- 库存记录同款家具总数、摆放数和可用数。
- 图鉴记录曾经获得过的不同家具。
- 重复家具增加库存，不重复增加图鉴进度。
- 家具未来被消耗后，图鉴记录仍保留。

完成定义：

- 不允许可用数量变成负数。
- 库存数据与摆放数据不一致时能检测并修复或拒绝加载。

### M3-05 实现奖励领取界面（P0，待验收）

任务：

- 显示当前待领取数量和下一件进度。
- 支持一次领取全部已累计单位。
- 按顺序展示每件家具的名称、档位和是否首次获得。
- 领取完成后立即写入存档。

完成定义：

- 重复点击领取不会重复发奖。
- 中途关闭展示界面不会丢失或重复奖励。

### M3-06 实现家具锚点（P0，待验收）

原型锚点：猫窝、食盆、地毯、桌面、玩具。

任务：

- 为房间定义每类锚点位置、旋转和缩放规则。
- 仅允许匹配类型的家具进入锚点。
- 更换家具时，旧家具回到可用库存。
- 明确空锚点和移除家具操作。

完成定义：

- 家具不会重叠生成或残留重复实例。
- 更换、移除和重启后库存数量一致。

### M3-07 实现家具界面（P0，待验收）

任务：

- 按锚点或档位筛选。
- 显示总数、摆放数和可用数。
- 区分已获得和图鉴未解锁家具。
- 从家具详情进入摆放或替换流程。

完成定义：

- 玩家无需说明即可理解哪些家具能摆在哪里。
- 没有可用数量的家具不能再次摆放。

### M3-08 扩展存档（P0，待验收）

保存内容：

- 猫外观选择。
- 猫基础数值。
- 在线累计剩余进度和待领取单位。
- 家具库存和图鉴。
- 每个锚点当前摆放家具。
- 设置选项和昼夜模式。

完成定义：

- 写入采用临时文件或备份策略，避免中断导致主存档损坏。
- 存档包含版本号，并为字段新增预留迁移入口。
- 损坏存档不会阻止程序启动。

### M3 里程碑验收

- 调试加速和正式速度下均能正确累计。
- 可连续领取多件家具，无重复发奖或丢失。
- 库存、图鉴、锚点摆放完整联动。

- 批量抽取测试通过。

## 8. M4：可试玩版本

### M4-01 首次启动与猫外观（P1，待验收）

当前美术资产暂未提供体型 BlendShape，原型阶段先验收 2 种毛色；2 种体型推迟到带有正式体型参数或独立模型的猫咪资产到位后恢复。

任务：

- 首次启动展示简短欢迎流程。
- 提供 2 种毛色；正式资产到位后补回 2 种体型。
- 预览选择结果并确认。
- 确认后进入主场景并保存。

完成定义：

- 未完成选择时退出，下次启动可继续。
- 外观选择不会影响存档中的家具和设置。

### M4-02 完成原型设置项（P0）

实现：

- 窗口置顶。
- 点击穿透。
- 桌宠缩放。
- UI 缩放。
- 主音量和音效音量。
- 30、60 和不限制帧率。
- 昼夜模式。

完成定义：

- 设置即时生效并持久化。
- 点击穿透开启后仍有可靠方式重新打开操作界面。
- 非法存档值会回退到默认设置。

### M4-03 完成反馈与音频基线（P1）

任务：

- 为关键互动提供统一反馈优先级。
- 调整音量，避免桌宠在后台突然发出过强声音。
- 限制气泡、音效和特效的同时播放数量。
- 为首次获得稀有或珍藏家具提供更明显反馈。

完成定义：

- 连续互动不会造成音效叠加爆音。
- 反馈不会长时间遮挡桌面或猫主体。

### M4-04 行为节奏调优（P0）

目标：避免过度活跃和长时间无事发生。

测试维度：

- 20 分钟内各行为出现次数。
- 同一行为连续重复次数。
- 靠近镜头和气泡对工作的打扰程度。
- 睡眠持续时间是否过长。
- 猫离开画面是否容易被误判为故障。

完成定义：

- 20 分钟内通常可观察到至少 4 种行为。
- 同一特殊行为不会连续高频触发。
- 所有调整均通过配置完成。

### M4-05 稳定性与异常测试（P0）

覆盖：

- 连续运行 2 小时。
- 频繁打开、关闭 UI。
- 频繁切换点击穿透和置顶。
- 运行中切换昼夜和缩放。
- 在领取动画中退出。
- 在家具替换过程中退出。
- 存档文件缺失、损坏或版本不一致。
- 显示器分辨率或 DPI 变化。

完成定义：

- 无阻断性异常。
- 数据异常不会造成重复发奖或库存负数。
- 已知非阻断问题被记录并分级。

### M4-06 新玩家试玩（P0）

建议至少 5 名目标玩家，每人体验 1～2 小时。

记录：

- 5 分钟内是否找到手机托盘。
- 是否独立完成点击、喂食或呼唤。
- 是否理解家具领取与摆放。
- 主动查看猫和主动互动的次数。
- 认为最可爱、最困惑和最打扰的内容。
- 对“猫是否像活的”的 1～5 分评分。

通过建议：

- 至少 4/5 玩家能在 5 分钟内完成一次互动。
- 至少 4/5 玩家能在提示不超过一次的情况下摆放家具。
- “猫像活的”平均评分不低于 3.5/5。
- 没有超过半数玩家指出同一个严重打扰问题。

### M4-07 输出试玩构建与说明（P0）

交付物：

- Windows x86_64 原型构建。
- 版本号和构建日期。
- 操作说明与已知问题。
- 默认存档和清档方式。

## 9. 跨模块验收清单

### 窗口

- 无边框、透明、置顶可用。
- 拖动后不会完全移出屏幕。
- UI 打开时关闭穿透，关闭后恢复。
- 点击猫、点击 UI 和拖动窗口不互相误触。

### 猫咪行为

- 行为进入、更新、退出路径完整。
- 不可打断状态符合策划规则。
- 移动失败、动画缺失和目标缺失均有降级路径。
- 状态与数值可通过调试面板观察。

### 家具

- 奖励结算具备幂等性。
- 库存总数 = 可用数 + 已摆放数。
- 图鉴只记录是否曾经获得。
- 替换和移除不会复制或吞掉家具。

### 存档

- 所有 P0 数据均保存。
- 写入中断不会轻易损坏唯一存档。
- 新旧字段具备默认值或迁移入口。
- 读取失败时可以安全创建新存档。

### 性能

- 空闲桌宠不产生持续报错或明显内存增长。
- 原型目标帧率设置可生效。
- UI 关闭时不执行无意义的高频刷新。
- 行为决策无需每帧完整重算，可使用固定间隔或事件触发。
